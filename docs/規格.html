01為什麼另開專案

技術棧完全不同。活動快報是 GAS ＋ GitHub Pages，這套是 Cloudflare Workers。 兩者沒有任何共用程式碼，硬綁在一起只會互相拖累。

  • 爆炸半徑　邀請卡會持續改版，不該有機會弄壞已經穩定上線的活動快報
  • 權限模型不同　活動快報全公開；這套的維護介面必須擋住外人
  • 改動頻率差太多　活動快報幾乎不動，新專案初期會天天改

02系統架構

為什麼不用 GAS

你的活動快報裡有個 keepWarm() 觸發器每 5 分鐘跑一次，就是在對抗 GAS 冷啟動—— 這代表你已經吃過這個虧。

邀請卡是陌生人從 LINE 點開的。開場如果空白三秒，人就走了，沒有第二次機會。 Workers 幾乎沒有冷啟動，而且跑在離使用者最近的節點上。

換掉 GAS 順便解決了一個原本的妥協

靜態網站沒辦法針對每張卡產生不同的 LINE 預覽。Worker 是在伺服器端組出 HTML 的， 所以可以每張卡有自己的標題和預覽圖——而且網址也能做成乾淨的形式。詳見第 6 節。

只有一個 Worker，用路徑分流。維護介面不是另一個服務，是同一個 Worker 上被 Access 保護的一條路徑。

Worker 怎麼讀試算表

試算表是資料的家，但 Sheets API 不是一個快的資料庫——一次讀取大概 200～400 毫秒， 而且有每分鐘請求上限。直接讓每個訪客去打 Sheets API，就等於把 GAS 的慢換了個地方發生。

所以中間掛一層 KV 快取：

情境發生什麼速度
快取命中
（絕大多數情況）		Worker 直接從 KV 拿資料渲染約 5 毫秒
快取沒有讀 Sheets API，順手寫進 KV約 300 毫秒
維護介面新增／修改寫進試算表，同時寫進 KV連結產生當下就是對的
直接在試算表改等快取過期後生效最多 2 分鐘
維護介面讀取不走快取，直接讀試算表約 1 秒
快取只給公開卡片，維護介面一律讀即時資料

快取原本是為了讓陌生人從 LINE 點進來能秒開。但維護介面一起吃了它的副作用： 剛改完試算表，畫面還是舊的，看起來就像壞了。

所以拆開——維護介面的人是兩三個、一天開幾次，多等 300 毫秒毫無感覺， 換來的是所見即所得。維護介面另有一顆「重新整理快取」，是給公開卡片用的。

存取試算表要用服務帳戶

Worker 不是人，沒辦法用 Google 帳號登入。做法是在 Google Cloud 建一個服務帳戶， 把試算表分享給它的 email（給編輯權限），Worker 用它的金鑰換取存取權杖。

Workers 內建 WebCrypto，簽 JWT 換權杖大約三十行程式。 權杖有效一小時，一樣快取起來，不用每次重換。

免費額度

03資料表與設定

會變動的資料放試算表，幾乎不變的放設定檔。

設定檔（wrangler.toml）

教會資訊和雲端硬碟資料夾 ID 都在這裡，不進試算表。

# wrangler.toml
[vars]
CHURCH_NAME    = "真耶穌教會　黎明教會"
CHURCH_NAME_EN = "TRUE JESUS CHURCH"
CHURCH_ADDRESS = "台中市南屯區大墩四街 460 號"
CHURCH_PHONE   = "04-2380-9800"
CHURCH_MAP     = "https://maps.app.goo.gl/..."

SHEET_ID       = "<試算表 ID>"
POSTER_FOLDER  = "<海報資料夾 ID>"
ATTACH_FOLDER  = "<附件資料夾 ID>"
OG_IMAGE       = "<預設 LINE 預覽圖的檔案 ID>"

改這些要重新部署，但教會地址電話幾年才變一次，不值得為它做一張後台表。

服務帳戶金鑰不能放這裡

wrangler.toml 會進 git。金鑰要用 wrangler secret put GOOGLE_KEY 存成密文， 它只存在 Cloudflare 上，不會出現在程式碼裡。

試算表分頁

四個分頁。第一列是標題列，程式用標題文字對應欄位—— 所以標題不要改，但欄位順序可以隨意調、之後要加欄位也不會壞。

一張卡片可以邀兩場，只寫「我要參加」等於沒寫——不知道他要去哪一場。 所以卡片上是一場一顆按鈕，回覆欄存 2609-福音茶會,2609-秋季靈恩會， 跟活動欄同一套寫法。

預覽抓取不能算成開啟

把網址貼進 LINE，LINE 會先自己抓一次網頁來做預覽卡片——那不是人在看。 同一則訊息被轉貼幾次就抓幾次，不擋的話次數會虛胖，這欄就失去意義了。

渲染時看 User-Agent，是預覽爬蟲（LINE、Facebook 那幾種）就只渲染不計數。 計數本身放在回應送出之後做（ctx.waitUntil），不要讓訪客等寫入。

活動欄不能只放一個值

你要能選擇活動 ×2——一個人可能同時被邀去福音茶會和靈恩佈道會。 存成 2609-福音茶會,2609-秋季靈恩會。

這個決定要現在做，之後改資料結構很痛。

多頁掃描件怎麼呈現

〈蘇真玉見證〉是 6 頁掃描圖、沒有文字層，手機上沒辦法像文章一樣重排。第一版當圖片看：

  • 事先轉成圖片　在自己電腦上把 PDF 轉成 6 張 JPG 再上傳。Worker 不轉 PDF，那不是它擅長的事
  • 長邊 1600 px　幾乎所有人都用手機看，太小的掃描圖會糊到讀不動。1600 px 在高解析螢幕上放大也還清楚，單張大約 300～500 KB
  • 直式往下捲，不做左右翻頁　手機上捲動比翻頁自然，也不會有人卡在第一頁不知道要滑
  • 底下放一顆「下載完整 PDF」　想印出來或轉寄的人用得到

之後真的有人願意把內容打成文字，再升級成能重排、能搜尋的網頁版——那時只是多一種類型，資料結構不用動。

可用變數：{對象}、{稱謂}、{對象全稱}、{邀請人}、{活動}、{網址}。

變數代入不能用 \w

JavaScript 的 \w 只認 ASCII，{活動} 這種中文變數名一個都比對不到， 結果會把大括號原樣印在卡片上。要比對大括號之間的任意字元。

雲端硬碟的檔案怎麼進來

資料夾設成「知道連結的人可檢視」，維護介面貼分享連結，系統用正規式抽出檔案 ID 存進 file_id。

設定檔裡的資料夾 ID 用來在維護介面放一顆「開啟雲端資料夾」按鈕，方便上傳。

實測結果：列得出來，而且好用

服務帳戶的權杖打 Drive API 可以列出資料夾內容。系統靠這個做兩件事： 附件沒填檔案 ID 時照檔名自動補；從海報資料夾匯入活動（第 5 節）。

資料夾在「共用雲端硬碟」時，少兩個參數會回空清單而且不報錯

教會的海報與見證資料夾都在共用雲端硬碟裡。Drive API 的 files.list 必須帶 supportsAllDrives=true 和 includeItemsFromAllDrives=true，否則回傳的是空清單， 而且 HTTP 200——看起來像資料夾是空的。這種錯最難查，它不是錯誤，是安靜的空值。

海報與檔案欄「填什麼都認得」

活動表的海報欄、附件表的檔案欄，三種寫法都吃：檔案 ID、雲端硬碟分享連結、 或檔名開頭（例如 2026-09-20）。 海報資料夾本來就用 yyyy-MM-dd 活動名 當檔名，填日期最省事。

圖片走 Worker 代理

不要讓瀏覽器直接連雲端硬碟——慢，而且 Google 會限流。改成：

invite.li-ming-tjc.org/img/<檔案 ID>

Worker 抓一次後快取在邊緣節點，之後所有人都吃快取。 順帶好處是圖片變成同網域，LINE 預覽圖也能直接用這個網址。

Worker 這邊用讀試算表的那把服務帳戶權杖去打 Drive API （files.get?alt=media），建服務帳戶時多啟用一個 Drive API、多要一個 drive.readonly 範圍就好。

不要用 uc?export=view 那種公開網址

檔案雖然設成「知道連結的人可檢視」，但那條網址 Google 會導向確認頁、也會限流， 用在正式流程上不穩。反正權杖本來就有，走 API 反而省事。

05維護介面

invite.liming-tjc.org/admin　左邊新增邀請，右邊查名單。

預設不列任何名單，要先選邀請人

打開頁面只看到新增表單和一排邀請人（各自帶邀請筆數）。點一位才列出他的名單。

活動、信件模板、附件三張表目前直接在試算表維護，沒有做成頁籤—— 它們一季才動一次，做四套一樣的列表介面不划算。活動有例外，見下面的匯入功能。

從海報資料夾匯入活動

海報檔名的慣例是 yyyy-MM-dd 活動名，所以日期（含星期）、名稱、活動代號、 排序、檔案 ID 都能從檔名推出來。按一顆按鈕列出候選，勾選後寫進活動分頁。

  • 只列日期還沒到、而且活動分頁裡還沒有的（比對海報 ID 與活動代號）
  • 時間和標語推不出來——那些印在海報圖片裡，要人補
  • 地點填設定檔的「預設地點」
  • 檔名不符合慣例的會另外列出來提醒，不會默默略過
匯入必須讀即時資料，不能讀快取

候選清單如果來自快取，兩個人先後匯入時，晚的那個看到的是舊清單， 會把同一場再寫一次。維護介面的所有讀取都直接打試算表。

06網址與 LINE 預覽

乾淨網址，而且每張卡有自己的 LINE 預覽。

invite.li-ming-tjc.org/k7m2xq9v4bt3

這是換掉 GAS 最大的收穫。原本用 GitHub Pages 靜態託管時， 乾淨網址要靠 404.html 接管，代價是 HTTP 狀態碼真的是 404，LINE 預覽縮圖不會出現—— 所以當初只能退而求其次用 ?k= 查詢字串。

Worker 是在伺服器端組 HTML 的，路由自己決定，狀態碼正常、網址乾淨、預覽標籤還能客製：

<meta property="og:title"       content="陳志成 邀請你參加福音茶會">

<meta property="og:image"       content="https://invite.li-ming-tjc.org/img/<海報 ID>">

對方在 LINE 收到的不是一條乾巴巴的網址，而是寫著他被誰邀請、海報縮圖在旁邊的卡片。 對點開機率的影響很大。

原本的計畫走不通：Wix 不讓改名稱伺服器

原訂掛在 invite.li-ming-tjc.org，需要把 DNS 交給 Cloudflare。 但那個網域是透過 Wix 買的（註冊商 Tucows），而 Wix 不允許變更 Wix 網域的名稱伺服器——官方說明的唯一建議是把網域轉出去。 網域上掛著 clientUpdateProhibited 鎖就是這件事的具體表現。

退而求其次的「只把 invite 子網域委派給 Cloudflare」也不行： 那叫 subdomain zone，Cloudflare 只開放給 Enterprise 方案。

實際做法：另外註冊 liming-tjc.org

在 Cloudflare Registrar 直接註冊新網域，約三十秒完成， 名稱伺服器天生就是 Cloudflare 的——不用碰 Wix、不用等 NS 生效、沒有轉移風險。 子網域 invite.liming-tjc.org 由 custom_domain 自動建 DNS 記錄並簽憑證。

教會原本的 li-ming-tjc.org（GitHub Pages）完全沒有動到。 兩個網域可以並存，日後要把舊的轉出 Wix 再說。

加上自訂網域時，workers.dev 會被預設關掉

設定檔裡一加 routes，workers.dev 那條就自動停用， 而新網域的憑證要幾分鐘才簽好——中間那段時間兩邊都不通。 要明確寫 "workers_dev": true 保留它，已經發出去的連結才不會壞。

07權限設計

現況：維護介面沒有身分驗證，任何人都進得去

原訂用 Cloudflare Access（email 白名單、一次性驗證碼、零行程式碼、50 人內免費）。 評估後決定不設——不想再多一套帳號系統。這是明知代價的取捨，記在這裡：

知道網址的人可以看到名單（姓名、邀請人、個人化開場）、新增邀請、停用別人的卡片。 緩衝只有兩層：robots.txt 擋搜尋引擎收錄，以及「預設不列名單、要先選邀請人」。

要補起來的話，Access 的前提條件現在都齊了（網域已在 Cloudflare）， 設定約五分鐘：保護 admin 這一條路徑即可——維護 API 都在它底下。 /api/rsvp 千萬不能一起擋，否則「我要參加」會壞掉。

維護介面公開邀請卡
路徑/admin、/admin/api/*/<代碼>、/img/*、/api/rsvp
驗證無無
可做的事讀全部 ＋ 寫只讀單一筆，只能寫自己那筆的回覆

「我要參加」是公開路徑上唯一會寫入的東西

三道防線：

  • 只認完整正確的 12 碼　約 8×1017 種組合，猜不到；而且只接受這張卡片真的邀了的活動代號
  • 同一代碼、同一場，一分鐘只寫一次　KV 擋著。節流的鍵要帶活動，否則複選時按了第一場會把第二場擋掉
  • 已經回覆過就不再寫　重複按沒有意義

最壞情況是拿到連結的人手滑按了參加——打通電話確認就好，不是災難。

公開路徑只接受「完整正確的代碼」，一次回傳一筆，不提供列表。沒有代碼就什麼都拿不到。

隨機碼是「猜不到」，不是「有權限管制」

拿到網址的人都看得到。適合放邀請函、活動資訊；不要放電話、地址、奉獻紀錄。

代碼至少 12 位、要用亂數，絕不能用流水號——否則改個數字就翻到別人的卡片。

網址代碼

就是網址最後那串，整個系統唯一對外的識別碼，規則要定死。

項目規則
長度12 碼
字集23456789abcdefghjkmnpqrstuvwxyz（31 字）
大小寫一律小寫，比對時不分大小寫
組合數約 8×1017

字集刻意拿掉 0 1 i l o—— 萬一有人要口頭念或手打，這幾個最容易搞混。

代碼裡不能編進任何有意義的東西

不要放姓名縮寫、日期、流水號。只要有規律，別人就能推算出其他人的卡片。

Worker 產生代碼的寫法：

function newCode() {
  const A = '23456789abcdefghjkmnpqrstuvwxyz';
  const bytes = crypto.getRandomValues(new Uint8Array(12));
  return [...bytes].map(b => A[b % A.length]).join('');
  // 寫入前仍要查一次 invites，確認沒撞到
}

Workers 內建 WebCrypto，crypto.getRandomValues() 是密碼學等級的亂數， 不像 Math.random() 有被推算的疑慮。

環境變數

設定值放 wrangler.toml 的 [vars]，命名沿用全大寫底線慣例（見第 3 節）。

09建置步驟

全部完成，2026-08-28 上線

下面這份清單留著當紀錄。實際執行時有兩處與計畫不同： 第 13 步（搬 DNS）因為 Wix 不讓改 NS，改成註冊新網域（第 6 節）； 第 14 步（Access）經評估後決定不做（第 7 節）。

可以打勾，進度存在這台裝置的瀏覽器裡。
展開成每步的做法、驗收條件與活動前的回推時程，見 邀請卡施做計畫。

  1. 註冊 Cloudflare 帳號，裝 wrangler
    npm i -g wrangler，然後 wrangler login。先不要動網域
  2. 建立 repo tjc-km/invite 與 Worker 骨架
    wrangler init，先讓 xxx.workers.dev 回一句 Hello 就好
  3. 建立 Google 試算表「邀請卡資料」，開 4 個分頁
    欄位照第 3 節。第一列是標題列，程式靠標題文字對應
  4. 建立服務帳戶，把試算表分享給它
    Google Cloud 建專案 → 建服務帳戶 → 啟用 Sheets API → 下載 JSON 金鑰。
    試算表按「共用」，貼上服務帳戶 email，給編輯者權限
  5. 金鑰存成 Worker secret
    wrangler secret put GOOGLE_KEY。絕對不要貼進 wrangler.toml，那個會進 git
  6. 建立 KV 命名空間
    wrangler kv namespace create liming-invite-cache，綁進 wrangler.toml
  7. 先讓 Worker 讀得到試算表
    簽 JWT → 換權杖 → 讀一列印出來。這是整套最容易卡的一步，先單獨做通
  8. 雲端硬碟建兩個資料夾，權限設「知道連結的人可檢視」
    海報、附件各一個，資料夾 ID 填進 wrangler.toml
  9. 把〈給慕道者的信〉改成模板，塞測試資料
    原稿的 ＸＸ 換成 {對象} 和 {邀請人}。順便手動填 2 筆活動、1 筆附件、1 筆邀請
  10. 做公開邀請卡的渲染 ＋ KV 快取
    原型的版面直接沿用，改成 Worker 在伺服器端組 HTML。先做這個，看得到東西才有動力
  11. 做圖片代理 /img/<檔案 ID>
    用 Cache API 快取，確認海報載得出來
  12. 做維護介面的「邀請名單」頁籤
    能新增、能產生代碼、能複製連結就夠了，其他頁籤之後再補。
    寫入時記得同步更新 KV
  13. 搬 DNS 到 Cloudflare，掛上子網域
    先抄下 Wix 現有的所有 DNS 記錄，尤其 MX。GitHub Pages 那幾筆設成「僅 DNS」
  14. 設定 Cloudflare Access
    保護 /admin 和 /api/*，列出允許的 email。用無痕視窗確認擋得住
  15. 端到端測試
    新增一筆 → 複製連結 → 用另一支手機從 LINE 開 → 確認預覽縮圖和標題有出來

2026-08-28 定案

記錄開啟次數與最後開啟

只記這兩欄，不記 IP、不記每一次的時間點。對關懷有用的資訊就是「他到底看了沒」。 預覽爬蟲不計數，寫入放在回應之後——見第 3 節。

見證先當圖片看，之後可能升級網頁版

PDF 留在雲端硬碟，事先轉成 6 張長邊 1600 px 的圖片。 幾乎都是手機在看，圖不能小。呈現方式與尺寸見第 3 節。

雲端硬碟檔案一律「知道連結的人可檢視」，以好作業為準

維護時只要把檔案丟進資料夾、複製連結貼進試算表，不用逐一設權限。 Worker 讀檔走服務帳戶權杖 ＋ Drive API，不靠公開網址。

2026-08-28 追加定案

卡片可以回覆。「我要參加」做了，一場一顆按鈕，寫回試算表的回覆欄。 防灌水機制見第 7 節。

見證改走 Drive 預覽頁，不轉圖片。抽驗〈04-04-禱告生活-蘇真玉〉： 6 頁掃描、沒有文字層、16.9 MB。整份丟給手機要等十幾秒， 而 Google 的檢視器逐頁串流，點下去就看得到第一頁。 54 篇見證一體適用，不必為換一篇就轉一次檔。讀起來吃力再回頭轉圖片。

維護介面不設身分驗證。見第 7 節，代價寫在那裡。

還沒決定

  • 邀請人要不要建一張表　現在是自由輸入。建表可以避免「陳志成／陳誌成」這種不一致，但多一層維護

  • 試算表的共用權限　目前是「知道連結的人可檢視」，任何人拿到 ID 就能下載整份名單
